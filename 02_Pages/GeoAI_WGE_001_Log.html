Turn 5 — the geometry

Natural Earth, which cartopy ships, has no US counties. The Census TIGER host is refused by the egress allowlist. raw.githubusercontent.com is permitted, and the standard FIPS-keyed county GeoJSON is mirrored there.

import urllib.request, json, os, cartopy
url = ("https://raw.githubusercontent.com/plotly/datasets/master/"
       "geojson-counties-fips.json")
with urllib.request.urlopen(url, timeout=120) as r:
    gj = json.load(r)
tx = [f for f in gj["features"] if f["properties"].get("STATE") == "48"]
out = {"type": "FeatureCollection",
       "features": [{"type": "Feature",
                     "properties": {"NAME": f["properties"]["NAME"],
                                    "FIPS": f["properties"].get("GEO_ID","").split("US")[-1]},
                     "geometry": f["geometry"]} for f in tx]}
d = os.path.join(cartopy.config["data_dir"], "extra")
os.makedirs(d, exist_ok=True)
json.dump(out, open(os.path.join(d, "tx_counties.geojson"), "w"))

The last line is the step most likely to be skipped and the one that saves the most time. Before drawing anything, every county name the sources had produced was checked against the names in the geometry:

want = ["Zavala","La Salle","Edwards","Gillespie","Tom Green","Coke","Kerr",
        "Kimble","Sutton","Uvalde","Val Verde","Webb","Bandera","Brewster",
        "Crockett","Jim Hogg","Medina","Pecos","Presidio","Schleicher","Starr",
        "Terrell","Zapata"]
missing = [w for w in want if w not in names]

none. A join on text keys is the most common silent failure in this kind of work — "La Salle" against "LaSalle", "Tom Green" against "TomGreen", a trailing " County" on one side. Checking it before the map is drawn turns a wrong map into an error message. In this case the mirror's NAME field matched the sources' spelling exactly, which was luck, not design; the check is what converted luck into knowledge.

Turn 6 — the data into the register, before the picture

The county facts were written into content/projects/screwworm_chronology.yaml as four dated slices, each with its source URL and retrieval date, under a header that states plainly what the block is not:

WHY THIS BLOCK EXISTS AND WHY IT IS NOT A CASE COUNT Asked for a map of Texas counties with documented cases through time. The request is reasonable and the data to answer it exactly does not exist in public form. What exists is two different things, published by different people at different cadences: INFESTED ZONES are enumerable. Somebody publishes the list of counties under movement restriction, in text, and it is complete on the day it is published. CONFIRMED CASES are counted but not located. The running total is published — 47 by late August — while the county of each case lives only in an embedded APHIS dashboard that publishes no county list and no export. So on any given date the number of counties this file can NAME is far smaller than the number of detections that have occurred. That gap is the point of the map, not a defect in it. […] named_cases is therefore always a LOWER BOUND and is marked as one. Nothing in this block should be summed and reported as a case count.

Read the two middle columns down the page. Detections go 1, 9, 44, 47. Nameable counties go 1, 5, 11, 13. The record of what happened and the record of where it happened are diverging, and by the last row 34 of 47 detections have no county in any public text.

The block also carries a what_a_map_of_this_may_not_say list, written before the map existed. Quoted from the register, word for word, as a list rather than a block quotation so that it renders as one (an indented bullet list flattens into a paragraph beginning with a dash, which the accessibility gate refuses):

  • That a county with no shading has no cases. It means no source published a county.
  • That the two layers are the same thing. A zone is a restriction on movement drawn around an area; a named case is one animal. They are published by different bodies for different purposes and they do not nest.
  • That any of this is at sub-county resolution. Every zone is described as covering PARTS of the counties named, and this file holds whole counties.

Turn 7 — building the map, and what went wrong

The figure is generated by texas() in tools/slides/figs_w02.py: four Albers equal-area panels, one per slice, gold for zone counties, maroon for counties with a named case, drawn from the register.

First render — the failure that a build cannot catch

The four maps drew correctly and every panel caption was missing. The build reported success.

The cause: the captions were written with the file's own text helper, which places text in data coordinates. On a projected map axes, data coordinates are meters in a conic projection, so y = 1.075 put every caption a meter above the equator — far outside the visible extent. Nothing errored. A label off the edge of a map is not an error to matplotlib.

The fix, and the comment left in the code so the next person does not repeat it:

# Panel captions are FIGURE text. Written as axes text they were placed
# in data coordinates on a projected axes and silently landed outside
# the visible extent -- the panels rendered captionless and the build
# said nothing, because a label off the edge of a map is not an error.

This was caught by looking at the rendered image. It could not have been caught any other way, and it is the same lesson the project already carries as R41: look at the rendered pages before saying a document is done.

Second render — a collision, fixed by moving the layout rather than the text

The panel dates collided with the figure's subtitle. Panels moved down, subtitle up. Trivial, and recorded because it is the ordinary half of this work.

What the assistant refused to do, and why it matters most

A choropleth of confirmed cases per county was the obvious deliverable and it would have been wrong. Thirteen counties shaded, 241 blank, on a map captioned "documented cases" — and thirty-four real detections rendered as absence.

That is precisely the error the W02 deck spends a slide teaching: a detection map is a surveillance map. The deck that says so would have committed it in the same session, on the following slide, in the instructor's own state.

What was built instead: two layers, labeled as different kinds of fact, with the count of each printed under every panel, and a footer that says in bold what the white counties mean:

A county with no color does not mean no cases — it means no source published a county. At the last date, 34 of 47 detections have no county in any public text.

Two things a student should take from the failures rather than the successes.

  1. The assistant's first instinct about the data was wrong, and saying so in advance is what made that cheap. An unstated assumption would have produced a map built on the register alone and nobody would have gone looking.
  2. The map that was easiest to build was the one that would have lied. No tool, gate or check in this project would have stopped it. The only thing standing between the easy map and the honest one was somebody asking what the white counties meant.

What is still not known, and would change the map

  • The 34 unlocated detections. In the APHIS dashboard, which publishes no county list and no export. A student with browser access could transcribe them; that is a real, finishable component and it is worth marks.
  • Whether the zones were released. TAHC's page and the APHIS action reported by trade press disagree, and the register holds both.
  • Sub-county geography. Every zone covers parts of counties. Whole counties are drawn. The map is coarser than the fact it represents, and says so.
