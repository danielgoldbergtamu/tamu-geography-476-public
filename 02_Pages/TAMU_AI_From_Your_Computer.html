Everything GEOG 476 asks of you can be done in the browser at chat.tamu.ai, and the Knowledge Collections feature already handles working with your own files. This page is for the students who want the tools on their own machine — usually because they are scripting an analysis and want the model in the same place as the code.

Read the last section before you start. There are three things about this route that will bite you mid-semester if nobody tells you, and one governance question you should not answer on your own.

1. Get an API key

Profile icon → Settings → Account → Show next to API Key → + Create new secret key, then copy it.

Two conditions that silently break keys. Both are in the university's own documentation and neither is obvious:

  1. You must create at least one chat in the web console before the key works at all.
  2. You must create or update a chat at least once every 30 days or the key stops working.

That second one is the one that gets people. Set up a CLI in week one, live in the terminal, never reopen the browser, and around week six you get an authentication error that explains nothing. Open chat.tamu.ai and send one message every few weeks. Put a reminder in your calendar.

Treat the key like a password. Do not paste it into a document, a screenshot, a ticket, a Discord message, or a file you might commit to git. It authenticates you against a service approved for regulated university data.

2. Point a tool at the endpoint

The Texas A&M University endpoint is:

https://chat-api.tamu.ai

The same host speaks more than one protocol, which is why so many tools connect:

Model names carry a protected. prefix — for example protected.gemini-2.5-flash-lite, protected.Claude Sonnet 4.6, protected.gpt-4.1. Get the current list by asking the API:

Windows PowerShell

$env:KEY = "YOUR_API_KEY_HERE"
Invoke-RestMethod -Uri "https://chat-api.tamu.ai/api/models" `
  -Headers @{Authorization = "Bearer $env:KEY"} -Method Get |
  Select-Object -ExpandProperty data | ForEach-Object { $_.id }

macOS / Linux

export KEY=YOUR_API_KEY_HERE
curl -s https://chat-api.tamu.ai/api/models \
  -H "Authorization: Bearer $KEY" | jq -r '.data[].id'

If that returns a list of model names, everything downstream will work. If it does not, stop here and fix it before installing anything.

3. The three tools A&M documents

These are the supported route. If something breaks and you email the help desk, these are the ones they will recognize.

OpenCode — a coding agent in the terminal

Install with winget install SST.opencode (Windows) or brew install opencode.

Create %USERPROFILE%\.config\opencode\opencode.json (or ~/.config/opencode/opencode.json):

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "chat.tamu.ai": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "TAMUS AI Chat API",
      "options": { "baseURL": "https://chat-api.tamu.ai/api" },
      "models": {
        "protected.Claude Sonnet 4.5": { "name": "Claude Sonnet 4.5" },
        "protected.gemini-2.5-flash-lite": { "name": "Gemini 2.5 Flash Lite" }
      }
    }
  },
  "model": "chat.tamu.ai/protected.Claude Sonnet 4.5"
}

Run opencode, type /connect, search for tamu, and paste your key when asked. It is stored separately from the config file.

Claude Code — the same idea, Anthropic's client

winget install Anthropic.ClaudeCode or brew install --cask claude-code.

# claude.env.ps1
$env:ANTHROPIC_BASE_URL = "https://chat-api.tamu.ai/api"
$env:ANTHROPIC_AUTH_TOKEN = "<your key>"
$env:ANTHROPIC_MODEL = "protected.Claude Sonnet 4.6"

Then . .\claude.env.ps1 and claude. Check with /model.

This uses the Claude Code software against A&M's endpoint. It is not an Anthropic subscription and does not give you one.

LLM — one-shot questions from a script

pip install llm, then llm keys set chat.tamu.ai. The university's docs carry a setup script that registers every available model. Afterward:

llm "explain what a spatial join does"
llm -x "write a python script that reprojects a shapefile" > reproject.py

Useful when you want a model inside a pipeline rather than a conversation.

4. Desktop apps with a normal interface

Several free desktop applications accept a custom OpenAI-compatible endpoint and will connect to https://chat-api.tamu.ai/api with your key. They give you a chat window rather than a terminal, and most can point at a local folder.

Ones that work this way include Chatbox, Jan, AnythingLLM and Msty, and in VS Code the Continue and Cline extensions.

Read this before you install one.

These are third-party applications that the university has not reviewed. Using one means putting a credential for a HIPAA/FERPA-approved endpoint into software nobody at A&M has vetted, on a machine that may hold client data. That is a real question and it is not one for you or me to answer casually.

So:

  • Ask first. helpdesk@tamu.edu — tell them the application, that it stores a TAMU AI Chat API key locally, and that you want to know whether that is acceptable. It is a short email and the answer is useful to everyone.
  • Until you have an answer, do not put client material through one. The browser and the three documented CLIs are unambiguously fine; that is what they are for.
  • If you install one anyway, keep it to your own coursework, and remember the key is yours — anything done with it is attributed to you.

I would rather you asked and got a yes than assumed and got it wrong. This is also good practice for the actual job: the question "has anyone approved this tool for this class of data?" is one you will be asked to answer for real.

If you want an agent, not a chat window

Claude Code already does this — section 3 above shows it, and it is the route to use. What you cannot do is the thing everyone asks for first: point Claude Desktop, or any of the polished graphical clients, at TAMU AI. Those apps have nowhere to put a custom endpoint, so the key has no home in them. That would be the nicest setup available and it is not currently possible.

If you want an agent with an interface rather than a terminal, the workaround is an agent platform that does take a custom endpoint. Hermes is the one I use: you install it on your own machine, point it at https://chat-api.tamu.ai/api with your key, and get agent behavior running on the university credits rather than on a subscription of your own. Everything in the box above applies to it — third-party software holding a credential for a protected endpoint, so ask the help desk before client material goes through it.

This is optional and nobody needs it to pass. If you want it set up, ask me and I will walk you through it, in office hours or in a studio, once your basic setup in sections 1 to 3 is working.

5. Three things that will bite you

The budget is invisible from the API. You get a fixed token allowance per day, and the API cannot tell you how much is left — only the dollar-sign icon in the browser can. A long session against a large model will exhaust it without warning, and it resets in the early evening Central time, not at midnight.

The key expires from disuse. Thirty days without touching the web console and it stops working. See section 1.

The API is for individuals, prototyping and learning. The university is explicit about this: it is not for multi-user applications or anything production-shaped. If your project genuinely needs that, the answer is a cloud AI platform and a conversation with Technology Services, not this key.

6. If it stops working

  1. Send one message in chat.tamu.ai. This fixes the 30-day expiry and it is the most common cause by a wide margin.
  2. Re-run the /api/models call in section 2. If it fails, the problem is the key or the network, not the tool.
  3. Check the model name is exactly right, protected. prefix included.
  4. Check your budget in the browser.
  5. Still stuck: helpdesk@tamu.edu, and bring the exact error text.

Then bring it to studio. Somebody else has probably hit the same thing, and if they have not, it is worth the room knowing.
