In studio — the team

    How the session runs

    From your material to a live site

    A GitHub Pages site is one folder of files that GitHub shows as a website. The folder is a repository. When the repository is named yourname.github.io, GitHub publishes it at https://yourname.github.io, free, for as long as the repository is public. You need no software on your laptop. Everything happens in the browser.

    Claude writes the website. You supply every fact on it. The site is one file named index.html, with its styling (CSS) and its small interactive parts (JavaScript) inside the same file. Claude is good at the code and will invent facts if you let it, so the prompt tells it to use only your material, and you check every line afterward.

    What stays off your site. Your phone number, home address and student ID stay off it, because the whole internet can read it. Use an email you will keep after you graduate. Nothing from the client project goes on it until I have checked with the client, as we covered on Tuesday. You can describe your role and your method in words.

    Make your GitHub account and repository

    1. Go to github.com and select Sign up. Use an email you will keep after graduation.
    2. Choose your username carefully. It becomes your web address, so pick one you would put on a resume.
    3. Verify your email with the code GitHub sends.
    4. Select + at the top right, then New repository.
    5. Name it exactly yourusername.github.io, using your own username, all lowercase.
    6. Set it to Public, turn on the Add README switch, and select Create repository.

    Gather your material in one document

    Put everything the site will say into one document, so you can paste it into Claude in one piece:

    • Your name, and one line saying what kind of work you want.
    • Three or four sentences about you.
    • Your three pieces. For each one: the problem, what you did, what you found, and what you would do differently.
    • Your resume text, and the links you want on the site, such as LinkedIn or a StoryMap.
    • Your email address, and the file names of any images.
    • For a map: a CSV file of your points, with columns for name, latitude and longitude. Or the link to an ArcGIS Online web map or StoryMap that is shared with Everyone.

    Save the document as Word, PDF or plain text (.txt). TAMU AI Chat refuses Markdown (.md) files.

    Have Claude write your site

    1. Open TAMU AI Chat and choose a Claude model in the model picker at the top left. Typing claude in its search box lists them.
    2. Select + under the message box, then Upload Files, and attach your document and your CSV.
    3. Paste this prompt and send it:

    Build a one-page personal portfolio website as a single file named index.html, with all the CSS and JavaScript inside it. Use my attached files as the only source of facts. Include: a header with my name and one-line headline; an About section; three project cards that open when clicked to show the problem, what I did, what I found, and what I would do differently; an interactive Leaflet web map (from unpkg.com) for any project that has map data, on the Esri World Topographic basemap (https://server.arcgisonline.com/ArcGIS/rest/services/World_Topo_Map/MapServer/tile/{z}/{y}/{x}, attribution "Tiles © Esri"), with a popup for each point and the map data written inside the file; a Resume section; and a Contact section with my email as a link. If I give you an ArcGIS Online map or StoryMap link, embed it in an iframe. Keep the CSS short so the whole file fits in one answer. Make it readable on a phone. Do not invent employers, numbers, dates, links or skills. Where you need something I did not give you, write [ADD] instead.

    1. Select Preview above the code to see the site in the panel on the right. Click a project card and a map point to check they work.
    2. Ask for one change at a time until you like it. Then select Copy above the code to copy the whole file.

    If the code stops before its last line, the answer was cut off. The file must end with </html>. Ask: "Your answer was cut off. Write the complete index.html again, shorter."

    Getting a web map that works. These were tested in TAMU AI Chat before class.

    • Your own points. Give Claude a CSV with name, latitude and longitude. It writes the points into the file as a Leaflet map.
    • The basemap. Use Esri World Topographic, as the prompt says. OpenStreetMap and CARTO basemaps were blocked in the preview when we tested.
    • An ArcGIS Online web map or StoryMap. Share it with Everyone, copy its link, and give the link to Claude to embed.
    • Client data stays off your site until I have checked with the client.

    Put your site on GitHub

    1. In your repository, select Add file, then Create new file.
    2. Name it index.html, paste Claude's code, and select Commit changes.
    3. For images, select Add file, then Upload files. Use exactly the file names the code uses.
    4. Wait one to five minutes, then open https://yourusername.github.io.

    If your site does not appear, check these in order. The repository name must match your username exactly, in lowercase. The repository must be public. The file must be named index.html, at the top level of the repository and not inside a folder. Settings → Pages says when your site is live. A new site can take up to ten minutes.

    Edit your site from your own computer

    You can keep working on your site after class from your own laptop. You make a copy of the repository on your laptop, which is called cloning it. Then every change you commit and push goes live on your site automatically, usually within 1 to 5 minutes.

    1. Install GitHub Desktop. It is free from desktop.github.com, for Windows and Mac. Sign in with your GitHub account when it asks.
    2. Clone your repository. Select File, then Clone repository, choose yourusername.github.io, pick a folder on your laptop, and select Clone.
    3. Edit the page. Open index.html from that folder in any text editor, or replace its contents with a new version from Claude. Put images in the same folder.
    4. Commit the change. In GitHub Desktop, type a short summary of what you changed, such as "Added the flood map", and select Commit to main.
    5. Push it. Select Push origin. GitHub publishes the new version, and your site updates in 1 to 5 minutes.

    Before you start editing, select Fetch origin, then Pull origin. If you changed anything on the GitHub website, this brings that change to your laptop first, so the two copies do not conflict.

    If you already use git on the command line, the same steps are:

    git clone https://github.com/yourusername/yourusername.github.io.git
cd yourusername.github.io
git add .
git commit -m "what changed"
git push

    Turn one of your assignments into a portfolio

    The one-page site showed how it works. Now you build the pages an employer expects, from work you already did. Pick the assignment that shows your best judgment, from this course or any other. A portfolio site has six files, and every page shares one menu and one style file:

    Turn one of your assignments into a portfolio
    FileWhat it is
    index.htmlHome: your name, one line on the work you want, and your strongest project
    about.htmlAbout: who you are and what kind of job you are looking for
    projects.htmlProjects: a card for each piece of work, linking to its own page
    project-1.htmlOne full project page: the problem, your role, the data and method, a map or figure, what you found, and what you would do differently
    resume.htmlResume: your resume as a web page, with a link to download resume.pdf
    style.cssThe colors, fonts and layout every page shares
    1. Stay in the same TAMU AI Chat, so Claude still has your material.
    2. Attach the assignment and your resume as a PDF, using + and Upload Files. Name the resume file resume.pdf.
    3. Paste the second prompt and send it:

    Turn my site into a multi-page portfolio. Use my attached assignment, my resume and my earlier material as the only source of facts. Write one file per answer, starting with style.css, and wait for me to type next before each new file. The files: style.css, shared by every page; index.html, with my name, headline and one featured project; about.html, about me and the work I want; projects.html, a card for each project linking to its page; project-1.html, a full page for my attached assignment with the problem, my role, the data and method, a figure or a Leaflet map on the Esri basemap if I gave map data, what I found, and what I would do differently; and resume.html, my resume as a web page with a link to download resume.pdf. Every page links to style.css, has the same menu (Home, About, Projects, Resume), and has my email in the footer. Do not invent employers, numbers, dates, links or skills. Where you need something I did not give you, write [ADD] instead.

    1. Copy each file Claude gives you, then type next for the next one. One file per answer keeps each answer short enough not to be cut off.
    2. On GitHub, select Add file, then Create new file, for each one, using the exact file name Claude gives it. The new index.html replaces your one-page version. Upload resume.pdf with Add file, then Upload files.

    Check every page before anyone reads it

    1. Read every sentence on every page of your live site against your material. Delete anything Claude made up, and fill in or remove every [ADD].
    2. Look for lines Claude forgot to update, such as a footer that still credits a basemap you replaced.
    3. Click every menu link, project card and map point on every page.
    4. Open the site on your phone.
    5. Record in your AI Review Log what Claude wrote that you removed or changed.

    Review each other's work, here, now

    12 minutes, in class, and it replaces a Canvas peer review. Swap with the person next to you. Read theirs, then talk — do not write a document. You are reviewing Project Draft 2, which was due on Tuesday.

    What to look for

    • Could you re-run this method from the description alone? Where would you get stuck?
    • Is the pilot output actually shown, or only claimed?
    • Does the Status Report include problems, or only progress?

    No written review is submitted for this. What is submitted is what you do next: the change you make because of what you heard, recorded in your AI Method Log or your next draft. Feedback you did not act on is feedback you did not get — and the person who told you it was wrong is sitting next to you, so ask them.
